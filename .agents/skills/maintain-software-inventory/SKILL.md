# 维护软件清单

先读仓库根目录的 `README.md`、`winget.json`、`scoop.json` 和当前工作区差异。收录边界、管理器分工及例外以 README 为准；具体包与来源以清单为准，不在技能中复制一份。

## 保持轻量

- 仓库文本只描述当前事实、必要理由和用法。变更经过由 Git 记录，不写历史对照或维护流水账。
- “报告给我”默认在对话中汇报。原始导出、版本快照和查询日志放临时目录；只有用户明确要求落盘时才创建报告文件。
- 用满足当前请求的最小改动完成维护。不为一次维护新增通用框架、长期脚本、测试套件或重复文档；有明确的复用需求再考虑抽取工具。

## 维护清单

- 由用户请求决定增删、替换或来源调整，沿用已确认的范围。新增软件不要求本机已安装，删除条目也不要求本机已卸载；只有影响决策且无法从上下文判断的歧义才需要询问。
- 按精确包 ID、source / bucket、产品分支和发行渠道核对身份。相似名称、不同发行版或主程序附带文件不能直接当作同一包；多版本记录去重，来源不明的条目先报告，不猜包 ID。
- 只修改请求涉及的条目。新增应用时声明所需 bucket；删除或替换后，可清理本次改动涉及且已无引用的 bucket。遵守现有版本策略，避免序列化顺带改写时间戳等无关元数据。
- 来源地址变化时，结合包源、用户说明及必要时的实际 remote 核实，只维护当前有效地址。管理器、分支或渠道的替换需要符合用户意图，不能仅凭名称相近推定可替换。
- 单独的清单维护请求不包含实际安装、升级、迁移或卸载；只有用户已授权相应操作时才执行，无需对已有授权重复询问。修改仓库中的目标来源不代表本机已完成迁移。

## 按需盘点本机

仅在请求涉及本机对比、同步或需要确认已安装软件身份时使用；手动增删清单无需先扫描全部软件。

- 用 `winget list` / `winget export` 和 `scoop export` 获取包身份，按需补查卸载注册表、AppX、全局 CLI 包、PATH 或字体记录。区分独立软件、运行时、扩展和主程序附带文件。PowerShell 使用 `-NoProfile`，避免触发用户 profile 的副作用。
- 已安装不等于有意长期保留；未发现也不构成自动删除理由。同一软件的来源或渠道与清单不同时，报告差异，不为贴合本机状态盲目改写既有选择或添加重复条目。
- 导出只作参考，按已确认范围增量更新，不用完整导出覆盖清单。用户明确要求的增删或替换以其意图为准。

## 验证与汇报

- 检查 JSON 可解析、无重复软件、bucket 引用完整、结果符合本次增删或替换意图，以及 `git diff --check`。精确查询新增、来源变更或存疑的包；删除条目无需查询远端，已有有效查询结果可复用。
- 需要复用 `bootstrap.ps1` 校验时，只执行清单读取和校验函数。不要为验证清单直接运行整个脚本，它会安装软件；普通清单修改不要求实际安装或干净虚拟机恢复。
- 在对话中简要说明修改结果、关键差异、未纳入或未确认项和实际验证范围；详细程度按用户要求调整。不把临时分析写成仓库里的长期报告，也不把包源查询成功说成安装验证通过。
